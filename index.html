Review

過程、學習與規則

今日過程與修正

一開始只有總覽層，缺少細節清單 → 補上分層結構。

缺少表格與延伸連結 → 每個分類加入。

視覺僅文字 → 整合 Codex 六張圖與 Grok 簡易視覺（公開版本圖片仍在處理中）。

Calendar 從總覽移到最上方，後依使用者要求移到 Review 後面。

每個分類原本共用同一段總覽 → 改為各有自己的 Daily Briefing。

GitHub Pages 設定過程：手機版多次 404，改走桌面版後成功啟用。固定網址為 https://changyeeming.github.io/grok-digest/

從錯誤中學到的

總覽層不能取代細節；兩者需要同時存在。

手機版 GitHub Settings 經常隱藏或 404，需切換桌面版或給直接路徑。

過程修正必須被記錄，否則每天都像從零開始。

AI Takeaway

單一高影響政治事件與多個本地脆弱點疊加。反應速度快於結構改變。今天最難也最值得記錄的，是把網站從本機檔案變成可自動更新的公開網址——過程中多次走錯路，最終靠切換桌面版完成。

當前規則（MVP 1.0）

觸發詞：Go 或 Grok Digest。

產出單一檔案或更新公開 repo。結構包含：分類導覽、各分類自己的 Daily Briefing、細節、表格、延伸連結、視覺、Review、Calendar。

Review 必須包含：當日過程修正與錯誤、從中學到的正確做法、AI takeaway、當前規則版本，以及重要技術設定過程。
